# Week10：Hack 組譯器（Nand2Tetris Project 6）

## 摘要

本週作業是用 Python 實作 Nand2Tetris 課程的 Hack 組譯器：讀入一份 `.asm` 組合語言檔，輸出對應的 `.hack` 二進位機器碼檔。組譯器完整支援 A 指令與 C 指令、符號（標籤與變數）、註解與空白處理，並通過課程提供的 `Add.asm` 測試，產出的 `Add.hack` 與標準答案一致。

## 檔案說明

| 檔案 | 說明 |
|---|---|
| `assembler.py` | 組譯器本體，約 90 行 Python |
| `Add.asm` | 課程範例：計算 `RAM[0] = 2 + 3` |
| `Add.hack` | 組譯後的機器碼輸出 |

## 使用方式

```bash
python assembler.py Prog.asm
```

會在 `Prog.asm` 同一資料夾產生 `Prog.hack`。例如：

```bash
python assembler.py Add.asm
# 完成: Add.hack (6 行)
```

以 `Add.asm` 為例，組譯結果如下：

| 組合語言 | 機器碼 | 意義 |
|---|---|---|
| `@2` | `0000000000000010` | A = 2 |
| `D=A` | `1110110000010000` | D = A |
| `@3` | `0000000000000011` | A = 3 |
| `D=D+A` | `1110000010010000` | D = D + A（即 5） |
| `@0` | `0000000000000000` | A = 0 |
| `M=D` | `1110001100001000` | RAM[0] = D |

## 實作說明

### 1. 指令編碼

- **A 指令**（`@xxx`）：左邊補 0 到 16 位元，`@2` 就是 `0000000000000010`。
- **C 指令**：格式固定為 `111 a c1~c6 d1~d3 j1~j3`，共 16 位元。

| 欄位 | 位元數 | 內容 |
|---|---|---|
| 前置 | 3 | 恆為 `111` |
| comp | 7 | 對照表 `COMP` 查表（a 位元 + 6 個計算位元） |
| dest | 3 | 由字母組合決定：A、D、M 有沒有出現 |
| jump | 3 | 對照表 `JUMP` 查表，沒寫就是 `000` |

comp 對照表另外加入了 `A+D`、`M+D` 這類交換律寫法，讓同一個計算的不同寫法也能正確組譯；dest 則是用 `'A' in d`、`'D' in d`、`'M' in d` 的方式產生位元，因此 `DM`、`MD`、`AMD` 等任意順序都通用，不必為每種組合建表。

### 2. 兩遍掃描（two-pass）

組譯器以兩次掃描處理符號：

1. **第一遍**：清理每一行（去掉 `//` 註解與所有空白），遇到 `(LABEL)` 就把標籤登記到符號表，值為「目前為止已出現的指令數」。標籤本身不產生機器碼。
2. **第二遍**：逐行翻譯。遇到 `@數字` 直接轉二進位；遇到 `@符號` 時先查表，查不到就當成新變數，從位址 16 開始依序配置。

預先內建的符號表包含：

| 符號 | 值 |
|---|---|
| `R0`–`R15` | 0–15 |
| `SP`、`LCL`、`ARG`、`THIS`、`THAT` | 0–4 |
| `SCREEN` | 16384 |
| `KBD` | 24576 |

### 3. 行的清理

`clean()` 先以 `//` 切開取前半，再移除所有空白字元，一行搞定註解、縮排與行內空白，例如 `  D=D+A  // 加上 3 ` 會變成 `D=D+A`。

## 測試結果

以課程提供的 `Add.asm` 測試，輸出的 `Add.hack` 共 6 行，可載入 CPU 模擬器驗證：執行後 `RAM[0]` 的值為 5，與 `2 + 3` 相符。

## 結論

這個作業的重點在於理解「組合語言 → 機器碼」的翻譯規則：A 指令只是補零的 16 位元位址，C 指令則是三段查表（comp、dest、jump）拼出固定格式。真正的難度在符號處理，用兩遍掃描就能解決「標籤指向未來位址」的問題——第一遍先把所有標籤的位置記下來，第二遍才翻譯指令，變數再從 16 開始配置。整個組譯器不需要正規表示式或複雜解析，用字串切割加查表就能完成。
